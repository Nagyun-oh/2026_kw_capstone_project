# 🚀 AI 앙상블 모델 학습 및 최적화 파이프라인 상세 보고서

본 문서는 웹 보안 위협(Web Attack)을 실시간으로 탐지하기 위해 구축된 **AI 모델의 진화 과정**을 상세히 기록한 문서입니다. 

초기 모델 탐색부터 극한의 설정값 최적화, 그리고 최종 가중치 투표(Voting) 비율 조정까지 총 3단계의 파이프라인을 거쳐 완벽한 방어력을 갖춘 최종 AI 번들(`.pkl`)이 탄생하게 된 배경과 결과를 누구나 이해할 수 있도록 정리했습니다.

---

## 🛠️ 단계 1: 모델 탐색 및 선정 (`model_selection.py`)

가장 먼저 수행된 작업은 "어떤 알고리즘이 보안 로그 분석에 가장 적합한가?"를 찾는 과정이었습니다. 수많은 머신러닝 모델을 얕게 학습시켜 보며 옥석을 가려냈습니다.

### 📍 주요 작업 및 인사이트
* **다양한 트리(Tree) 알고리즘 테스트:** 정형 데이터(표 형태의 데이터) 분류에 가장 강력한 성능을 내는 의사결정나무 기반의 앙상블 모델들을 집중적으로 테스트했습니다.
* **속도와 성능의 타협점 발견:** 초기에 시도했던 전통적인 `GradientBoosting` 모델은 연산 속도가 너무 느려 100회 학습에 12시간 이상이 소요되는 병목 현상(Bottleneck)을 일으켰습니다. 
* **해결책 도입:** 이를 대체하기 위해 히스토그램 기반으로 연산 속도를 20~30배 이상 획기적으로 끌어올린 **`HistGradientBoosting`**을 전격 도입하여 속도와 성능을 모두 잡았습니다.

### ✅ 최종 선정된 4대장 모델 (The Big 4)
이 과정을 통해 서로 성격이 다른 4개의 모델을 최종 후보로 선정했습니다.
1. **RandomForest:** 깊고 안정적으로 공격 패턴을 찾아내는 메인 브레인
2. **ExtraTrees:** 무작위성(Randomness)을 부여해 변칙적이고 낯선 공격을 잡아내는 유연한 뇌
3. **XGBoost:** 얕고 촘촘하게 오류를 수정하며 다른 모델의 실수를 보완하는 스나이퍼
4. **HistGradientBoosting:** 미세한 노이즈를 뭉툭하게 걸러내어 억울한 오탐을 막아주는 방패

## 🔥 단계 2: 극한의 하이퍼파라미터 튜닝 (`model_tuning_extreme.py`)

선정된 4개의 모델이 가진 잠재력을 100%로 끌어올리기 위해 **Optuna** 프레임워크를 사용하여 모델의 뇌 구조(Hyperparameter)를 극한으로 튜닝한 핵심 단계입니다.

### 📍 주요 작업 내용
* **데이터 증강 (SMOTE-ENN):** 심각한 불균형(정상 트래픽 >>> 공격 트래픽)을 해소하기 위해, 가짜 공격 데이터를 생성(SMOTE)하고 애매한 경계의 노이즈 데이터를 삭제(ENN)하여 모델이 헷갈리지 않도록 정답지를 깔끔하게 정돈했습니다.
* **총 400회의 튜닝 시뮬레이션:** 4개의 모델을 각각 100번씩, 총 400번 반복 학습시키며 각 모델의 '최적의 트리 깊이', '최소 샘플 수', '학습률' 등을 찾아냈습니다. (약 6시간 소요)

### 📊 튜닝 결과 및 특징
🔍 [심층 분석] 4대장 모델별 튜닝 결과와 역할 부여
* Optuna가 400번의 시험을 거쳐 각각의 모델에게 부여한 최적의 형태(Hyperparameter)는 놀랍게도 모델의 고유한 성격과 완벽하게 일치했습니다.

1. RandomForest (메인 브레인 / 심층 탐색가)

* 튜닝 결과: 나무의 깊이(Max Depth) 44층

* 분석: Optuna는 RandomForest에게 무려 44번이나 조건을 쪼개고 들어가는 '초심층 구조'를 허락했습니다. 이는 정상적인 브라우저 요청과 교묘하게 섞여 있는 복잡한 XSS, SQL Injection 공격의 미세한 패턴을 집요하게 파고들어 찾아내는 든든한 메인 두뇌 역할을 수행하게 만듭니다.

2. ExtraTrees (창의적 뇌 / 변칙 공격 방어자)

* 튜닝 결과: 나무의 깊이(Max Depth) 44층 + 극단적 무작위성(Random Splits)

* 분석: RandomForest와 동일하게 44층의 깊이를 가지지만, 데이터를 나누는 기준을 완전히 '무작위(Random)'로 설정하는 모델입니다. 학습 데이터에 없던 완전히 새로운 형태의 신종 공격(Zero-day)이나 페이로드가 살짝 변형된 변칙 공격이 들어왔을 때, 틀에 얽매이지 않는 유연한 사고로 공격을 잡아냅니다.

3. XGBoost (스나이퍼 / 정밀 교정기)

* 튜닝 결과: 나무의 깊이(Max Depth) 6층 / 나무의 개수(n_estimators) 941개

* 분석: 앞선 두 모델과 달리 깊이가 고작 6층밖에 되지 않습니다. 대신, 얕고 가벼운 나무를 무려 941개나 연속으로 세웠습니다. 이전 나무가 실수한 오답만을 집중적으로 다음 나무가 고치는 '부스팅(Boosting)' 방식의 특징을 완벽하게 살린 세팅입니다. 남들이 놓친 아주 얕은 논리적 허점을 941번 깎아내며 정밀 타격합니다.

4. HistGradientBoosting (안전장치 / 오탐 방지기)

* 튜닝 결과: 데이터를 통째로 보지 않고 구간(Histogram Bin)으로 묶어서 학습

* 분석: 다른 모델들이 공격이라고 너무 과도하게 확신(Overfitting)하여 억울한 정상 사용자를 차단하는 일(오탐)을 막아줍니다. 수치를 뭉툭하게 묶어서 판단하기 때문에 앙상블의 극단적인 판단을 부드럽게 눌러주는 아주 중요한 브레이크 패드 역할을 합니다.

* 요약 정리:
이 튜닝을 통해 4개의 모델은 서로 완벽하게 다른 형태로 진화했습니다.
* **RF & ET (깊이 44):** 나무의 뿌리를 지하 44층까지 깊게 내려 아주 복잡한 공격 패턴을 집요하게 추적하도록 세팅되었습니다. (Val F1-Score: 약 95.4%)
* **XGBoost (깊이 6):** 반대로 나무의 깊이를 6층으로 아주 얕게 제한하는 대신, 나무의 개수를 941개로 늘려 빠르고 넓게 위협을 탐지하도록 세팅되었습니다. (Val F1-Score: 93.8%)

### 💾 산출물: `model_bundle_extreme.pkl`
* 이 극한의 훈련을 마친 4개의 개별 모델 객체가 이 파일(번들) 안에 저장되었습니다. 하지만 이 모델들의 의견을 '몇 대 몇'으로 합칠지 아직 완벽하게 결정되지 않은 미완성 상태입니다.

## ⚖️ 단계 3: 글로벌 가중치 전수조사 (`weight_optimizer.py`)

마지막 단계는 4명의 뛰어난 AI 전문가(모델)가 낸 의견(확률)을 **어떤 비율로 반영해야 최종 탐지율이 가장 높은지**를 찾는 과정입니다.

### 📍 주요 작업 내용
* **훈련(Training) 생략, 연산 극대화:** 2단계에서 만들어진 `model_bundle_extreme.pkl`을 불러온 뒤 모델의 구조는 그대로 얼려둡니다(Freeze). 그리고 이미 계산된 예측 확률값에 곱해줄 가중치 비율만 **10,000번** 바꿔가며 최적의 비율을 찾았습니다. (약 20분 소요)
* **임계값(Threshold) 동시 탐색:** 단순히 50%를 넘으면 공격이라고 판단하는 것이 아니라, "과연 위협 점수가 몇 점일 때 경보를 울려야 가장 완벽한가?"를 동시에 탐색했습니다.

### 🏆 10,000번의 검증 끝에 찾은 황금비율 (Soft Voting)
* 🏆 최종 도출된 황금 비율 (수제 Soft Voting)
수많은 시뮬레이션 끝에 컴퓨터가 도출한 가장 완벽한 비율은 9 : 9 : 6 : 2 였습니다.

* 🌳 ExtraTrees (약 35%, 비중 9): 변칙 공격을 잡아내는 창의적인 의견에 가장 높은 점수를 주었습니다.

* 🌲 RandomForest (약 34%, 비중 9): 깊고 묵직한 메인 두뇌의 의견 역시 동등하게 가장 높은 비중을 둡니다.
(결과적으로 이 두 트리가 전체 투표권의 70%를 쥐고 앙상블의 뼈대를 튼튼하게 잡습니다.)

* 🚀 XGBoost (약 23%, 비중 6): 뼈대 모델들이 헷갈려하는 30%의 회색 지대(애매한 로그)가 발생했을 때, 예리한 스나이퍼인 XGBoost의 의견을 반영하여 판을 뒤집고 미탐을 막아냅니다.

* 🏎️ HistGradientBoosting (약 8%, 비중 2): 비중은 가장 작지만, 최종 결과가 선을 넘기 직전에 미세한 노이즈를 부드럽게 깎아내어 '정상 트래픽이 차단당하는 참사(오탐)'를 마지막 순간에 막아내는 필수 안전장치입니다.

* 요약 정리:
1. **ExtraTrees:** 34.94% (비중 9)
2. **RandomForest:** 34.34% (비중 9)
3. **XGBoost:** 23.21% (비중 6)
4. **HistGradientBoosting:** 7.51% (비중 2)

특정 모델 하나에 의존하지 않고, **`9 : 9 : 6 : 2`** 라는 가장 안정적이고 다채로운 투표(Voting) 생태계가 구축되었습니다.

### 🎯 철벽의 의사결정 기준 (Optimal Threshold)
* **최적 임계값: `0.6321` (63.21%)**
* 위협 확률이 50%를 넘는다고 섣불리 차단하지 않습니다. 위협 점수가 63.21%를 넘어서는 '확실한 공격'일 때만 차단하도록 설정하여 정상 사용자가 피해를 보는 **오탐(False Positive)을 획기적으로 차단**했습니다.

### 💾 최종 산출물: `model_bundle_ultimate.pkl`
* 4개의 최적화된 모델과 9:9:6:2의 가중치, 그리고 0.6321의 임계값 설정이 모두 담긴 **프로젝트의 최종 결정체**입니다. 
* 현재 FastAPI 서버(`main.py`)는 오직 이 궁극의 번들 파일 하나만을 바라보고 실시간 트래픽을 완벽하게 필터링하고 있습니다.

## 📈 최종 Test 세트 성능 요약 (Ultimate 버전 기준)
학습에 한 번도 사용되지 않은 미지의 데이터(Test Set)를 대상으로 측정한 최종 방어력입니다.

| 평가 지표 (Metric) | 수치 | 의미 |
| :--- | :--- | :--- |
| **Accuracy (정확도)** | **95.91%** | 전체 트래픽 중 정상/공격을 정확하게 맞춘 비율 |
| **F1-Score (조화평균)** | **94.96%** | 오탐과 미탐의 균형을 보여주는 실질적인 AI 성능 지표 |
| **Recall (재현율)** | **94.82%** | 실제 들어온 해킹 공격 중 AI가 놓치지 않고 잡아낸 비율 |
| **AUC-ROC** | **0.9892** | AI가 뱉어내는 위협 점수의 전반적인 신뢰도 (1에 가까울수록 완벽) |
| **FNR (미탐률)** | **5.17%** | 공격을 정상으로 착각하여 놓친 비율 (매우 우수한 수준) |

이 강력한 파이프라인을 통해 우리 프로젝트의 AI는 단순한 탐지기를 넘어, 낯선 변칙 공격까지 융통성 있게 방어해 내는 **견고한 SOC(Security Operations Center) 엔진**으로 완성되었습니다.

로컬 안내·보고서·공유 증거는 이 디렉터리에 모았다. [회차·집계](runs/) · [공유 증거](evidence/) · [초기 예비 정리](preliminary-summary.md) · [초기 실행기 이력](runner-v1.md). 2026/11/05 경로 이동 내역은 [이동 대조표](path-migration-20261105.json)를 참고한다. `build/test-runs/` 원본과 기존 증거 JSON의 내용·해시는 보존했다.

부하와 장애 시나리오는 별도 회차로 기록한다. 모든 실험에서 병목·결함이 발견돼야 하는 것은 아니며, 영향받은 시나리오를 개선 후 다시 확인한다. 현재 실행기는 로컬 HTTP 80, 1~5회/초, 1~120초를 허용한다. `--observe-pipeline`에서 연속 lag와 DB·AI 완료 대조를 추가하며 확인한 DB 저장 시각 기준도 명시한다. 부하 범위 확대·장애 주입·실패/DLT/알림 정합성 자동화는 후속 작업이다.

기존 v1 JSON과 실행기는 보존한다. v2는 별도 `scripts/testing/run_e2e.py`로 구현했고 [실행 가이드](e2e-runner.md)를 따른다. r13 실제 WAF·브라우저 연결 후 r15에서 정합성 결함을 확인해 보완했고, 격리 복구 검증 후 새 E2E r16~r18의 1건/초 단계를 모두 PASS했다. 이후 사용자와 범위를 좁혀 [3·5건/초를 각각 한 번 예비 확인](prechecks.md)했고 r21·r22 모두 PASS했다. 로컬 추가 부하는 여기서 마무리하고 EC2 측정 준비로 이동한다. 기존 실패 원본과 v1 결과는 보존한다.

v2의 정식 단계는 총 1→3→5회/초에 10초당 E2E probe 1개를 포함하고 각 120초·3회, 회차마다 워밍업 30초를 제외한다. 낮은 부하의 p99는 참고값, 단계 판정은 3회 모두 PASS로 정의한다. 이번 3·5건/초 각 1회는 같은 회차별 기준을 사용한 예비 확인이며 정식 단계 통과를 대신하지 않는다. 전체 규칙·초기 시간 상한·구현 상태는 [v2 명세](e2e-plan-v2.md)와 [기계 명세](e2e-plan-v2.json)를 따른다.

기존 실행기의 HTTP·비동기 지연 결과에는 p50을 참고 지표로 추가했다. HTTP `http_p50_ms`, 비동기 구간별 `p50_ms`를 JSON·보고서에 기록한다. 기존 합격 기준과 과거 보고서·원본은 보존한다. 전체 E2E v2의 추가 계측 구현 여부와는 구분한다.

## 병목·결함 개선과 재측정 연결

관측한 문제를 기준선·개선·재측정과 연결한다. 기존 결과는 아래에 보존하고, 이후에는 DB 조회 개선 등 측정에서 발견한 문제를 제한 없이 추가한다. 빈 사례를 미리 채우는 것은 요구하지 않는다.

| 사례·시나리오 | 로컬 기준선 보고서·ID | 관측 문제·원인 근거 | 개선 변경 SHA·설정 | 동일 조건 재측정 보고서·ID | 판정·비교 제한 |
| --- | --- | --- | --- | --- | --- |
| AI 결과 처리의 커밋 경합·예외 삼킴 | r15 | 커밋 전 AI 요청 발행 + 결과 예외 삼킴, 완료 119/121 | 사용자 구현 outbox·예외 전파·재시도/DLT, dirty 소스 해시·이미지 보존 | 격리 recovery r02 PASS + 실제 E2E r16~r18 모두 PASS, 완료 361/361 | 이번 조건의 미완료 재현 해소. 무장애 E2E와 격리 장애 검증을 구분. 속도 개선·종단 exactly-once 보장은 주장하지 않음 |

로컬→EC2 결과 차이를 개선율로 계산하지 않는다. 개선 외 조건이 달라지면 차이를 명시하고, 필요한 경우 새 기준선을 측정한다. 코드 변경 전후 SHA·환경·모델·정책·DB 규모·준비 요청·측정 기간·요청률·수집 방식을 대조한다. HTTP 평균·p50·p95·p99·최대값은 요청 건수·기간과 함께, 비동기 지연과는 분리해서 기록한다.

## 기록·재개 방법

1. [공통 가이드](../README.md)와 이 목차의 최근 기록에서 계측·목표·중단·복구 기준을 먼저 확인한다.
2. 실험 보고서는 `docs/testing/local/runs/<실험-ID>.md`, 원본은 `build/test-runs/<실험-ID>/`에 보존한다. ID의 환경은 `local`로 구분한다.
3. 실행·분석 후 이 목차에 회차·판정·보고서 링크를 추가하고, 개선·재측정이면 위 표에 기준선을 연결한다. 자동 실행기의 목차 갱신 기능은 현재 없다.
4. 이 목차에 관측한 사실·가설·진행 상태·다음 작업을 갱신한다. 실패·중단을 포함한 기존 판정·측정값과 원본은 보존한다. 2026/11/05의 문서 이동 이후에는 이 디렉터리의 경로를 사용한다.

**바로 다음 작업:** 로컬은 1건/초 3회와 추가 3·5건/초 각 1회 예비 확인까지 마무리했다. 다음은 [EC2 준비](../ec2/README.md): 대상 코드·이미지·DB SQL 적용, 원격 자원·Kafka·trace 수집, 발생기·인증·시계·차단 정책을 확인하고 소량 연결 검증부터 진행한다. 현재 로컬 전용 실행기를 그대로 EC2에 사용하지 않는다. DB 최적화는 쿼리·커넥션·락·outbox 적체 등 실제 병목 근거를 확보한 뒤 결정한다. 기존 r14·r15·r19와 원본·데이터·오프셋은 보존한다.

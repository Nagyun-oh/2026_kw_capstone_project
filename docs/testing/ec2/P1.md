## 임시 제외의 적용·복구 조건

아래는 실행 준비 단계에서 구현·수행할 절차이며 이번 P1에서 실행한 내역이 아니다.

1. 실행 직전 현재 발생기 IP·원래 WAF 제외 목록·해당 IP의 블랙리스트 등록 상태를 다시 보존한다. 기존 제외 목록의 다른 IP는 유지한다.
2. 확인한 단일 IP만 `WAF_SYNC_EXCLUDE_IPS`에 추가하고 WAF 재생성·설정 검증·동기화 확인을 수행한다. 실제 적용 전에 probe·부하를 보내지 않는다.
3. 소량 연결에서 정상 HTTP 응답·서버 requestId·실제 원격 IP·WAF 및 AI 처리·브라우저 알림을 확인한다. 예상 밖 403이면 부하를 시작하지 않는다.
4. DB에는 같은 요청의 WAF·AI 탐지로 발생기 IP가 등록될 수 있다. 이때 현재 적용 목록의 `excludedIps`에 `CONFIGURED_EXCLUSION`이 보고되는지 확인한다. DB에 아직 등록되지 않은 제외 설정 IP가 `excludedIps`에 나타나지 않는 것은 오류가 아니다.
5. 종료 시 실험 전에는 없었고 원인 위협이 해당 실험 요청에 연결되는 등록만 식별해 정리한다. 기존 블랙리스트·원본 로그·탐지 이력을 일괄 삭제하지 않는다. 실험 외 등록과 구분되지 않으면 임의로 삭제하지 않고 근거와 남은 조치를 보고한다.
6. **해당 IP가 블랙리스트에 남아 있는데 제외부터 해제하면 이후 JuiceShop 요청이 차단될 수 있다.** 시작 상태와 필요한 정리 결과를 확인한 뒤 이번에 추가한 제외만 원복하고, 동기화·기본 접근·서비스 상태를 다시 확인한다.

적용 단위는 공인 IP이므로 같은 NAT 출구를 공유하는 기기에도 해당할 수 있다. 임시 제외는 실험 시간으로 제한하고 일반 보호 정책으로 영구 유지하지 않는다. 이번 측정은 해당 발생기 IP의 블랙리스트 403 집행이 제외된 조건으로 보고한다.

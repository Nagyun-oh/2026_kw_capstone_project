# EC2 P3 실행기 환경 분리

완료일: **2026/11/05**

[EC2 진행표](README.md) · [P0 현황 수집](P0.md) · [P1 실행 조건](P1.md) · [검증 기록](evidence/20261105-p3-environment-separation.json)

P3는 기존 로컬 실행을 유지하면서 EC2의 대상 주소·계약·결과 경로를 분리하는 단계다. **환경 분리와 모의 검증은 완료했으며, EC2는 dry-run 계획 확인만 지원한다. 실제 부하·서버 접속·브라우저 연결은 이번 단계에서 수행하지 않았다.**

후속 [P4](P4.md)에서 수집 전용 SSH 조회를 추가했다. 아래 표·검증 수치는 P3 완료 시점의 기록이며, 현재 실제 부하는 P5~P8 준비 전까지 차단한다.

## 환경별 동작

| 항목 | local | ec2 |
| --- | --- | --- |
| 선택 | 기본값 또는 `--environment local` | `--environment ec2` |
| 요청 대상 | `http://localhost/` | `https://security-juiceshop-kw.duckdns.org/` |
| 관리자 화면 | `http://localhost:3000/` | `https://security-monitor-kw.duckdns.org/` |
| 요청 연결 | IPv4 loopback·HTTP Host localhost 유지 | 지정한 HTTPS 도메인·인증서·호스트 검증 유지 |
| 실험 ID 구분 | `local-e2e` | `ec2-e2e` |
| 보고서 | `docs/testing/local/runs/` | `docs/testing/ec2/runs/` |
| 원본 | `build/test-runs/<실험-ID>/` | 같은 상위 경로, 환경이 포함된 별도 실험 ID |
| 계약 | 기존 `local-e2e-v2` | `ec2-e2e-v1-draft`, 목표·중단 기준 미확정 |
| 수집 | 기존 로컬 Compose | P4 원격 수집 구현 전 |
| 실제 실행 | 기존 동작 유지 | P4~P8 준비 전 차단 |

대상 URL과 대시보드 URL은 환경별 허용 목록을 사용한다. 임의 호스트·포트·사용자 정보·쿼리·fragment가 있는 주소는 거부하며 리다이렉트를 따라 다른 대상으로 이동하지 않는다. HTTPS 인증서 검증을 끄는 옵션은 추가하지 않았다. 로컬 3회 집계기는 EC2 결과를 섞어 집계하지 않는다.

## 계획 확인

프로젝트 루트의 PowerShell에서 실행한다. 아래 명령은 실행 계획만 출력하며 HTTP 요청·브라우저·외부 명령·실험 파일 생성을 수행하지 않는다.

```powershell
.\build\e2e-venv\Scripts\python.exe -X utf8 scripts/testing/run_e2e.py --dry-run --rate 1
```

```powershell
.\build\e2e-venv\Scripts\python.exe -X utf8 scripts/testing/run_e2e.py --environment ec2 --dry-run --rate 1
```

EC2 계획에서 확인할 값:

- `environment`: `ec2`
- `schema`: `ec2-e2e-v1`
- `execution_ready`: `false`
- `planned_report`: `docs/testing/ec2/runs/` 아래 경로
- `cross_clock_policy`: `pending_p5`
- `targets_status`: `pending_p8`

EC2 `--execute`는 소량 연결 모드에서도 파일 예약·요청 발송 전에 거부된다. Python 요청 함수·실험 생성자와 k6 초기화에도 제한을 두어 준비 전 실제 실행을 막는다. 실행을 열려면 단순 플래그 변경이 아니라 P4~P8의 수집·감시·연결·판정 구현을 먼저 완료해야 한다.

## 현재 Windows PC에서 측정하는 의미

[P1](P1.md)에서 선택한 발생기와 알림 관측 브라우저는 현재 Windows PC다. 측정값은 다음처럼 분리한다.

| 측정 구간 | 해석 |
| --- | --- |
| WAF 진입 → 로그·AI 결과·WAF 탐지 커밋 | EC2 호스트의 시각을 사용하는 서버 파이프라인 지연 |
| PC에서 측정한 HTTP 응답 | PC↔EC2 네트워크와 서버 응답을 함께 포함한 값 |
| PC 요청 → 브라우저 알림 수신·DOM 표시 | 네트워크·서버 처리·PC 브라우저 지연을 포함한 사용자 관점 E2E |

PC HTTP·알림 시간을 별도 지표로 기록해도 발생기나 네트워크의 영향이 모두 사라지지는 않는다. 목표 요청률과 실제 송신·서버 도착률, 누락, 발생기 CPU·메모리·네트워크를 함께 확인해야 한다. 계측 시각을 직접 연결해 각 구간을 계산하며, HTTP 전체 시간에서 임의 값을 빼서 서버 시간을 추정하지 않는다.

이 확인은 P4 원격 수집과 P5 시계·자원 감시에서 보완한다. 로컬의 교차 시계 허용치 ±100ms나 SLO를 EC2 판정 기준으로 복사하지 않았다. 같은 리전의 별도 발생기로 변경하면 발생기·네트워크 조건을 새로 기록하고 기준선을 다시 정한다.

## 실제 검증

| 검증 | 결과 | 범위 |
| --- | --- | --- |
| Python 실행기 회귀·환경 분리 | **144개 통과**, 실패·오류·경고 0 | 모의 명령·임시 경로·가짜 브라우저, 실제 서비스 부하 없음 |
| local k6 inspect | 종료 코드 0 | localhost 매핑·TLS 검증 생략 금지·배경 요청 구성 확인. 요청 전송 없음 |
| ec2 k6 inspect | 종료 코드 107, 의도한 실행 제한 확인 | 초기화 단계에서 거부. 요청 전송 없음 |
| EC2 dry-run | 환경·주소·경로·미준비 상태 출력 | 결과 파일 예약·외부 접속 없음 |

원본 검증은 `build/testing-validation/p3-environment-separation/`의 `python-tests.json`, `python-tests.log`, `k6-inspect.json`에 보존했다. 공유 증거에는 결과와 변경 파일 SHA-256을 기록한다. 이는 성능 실측 보고서가 아니다.

Windows sandbox의 임시 파일 권한 제약으로 처음 일부 검증이 실패했으며, 허용된 환경에서 최종 전체 144개를 통과했다. k6 inspect는 공개 설정을 `-e`로 명시해 실행했다. 실제 EC2 TLS handshake·SSH 수집·로그인·부하·403은 이번 검증 범위에 포함되지 않는다.

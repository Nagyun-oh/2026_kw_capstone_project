## S — Situation

1 RPS·120초·3회는 모두 PASS했다. 개선 전에 입력 부하를 3 RPS로 늘려 서버 지연·처리 완료·적체 추이를 비교한다. 1 RPS 지연의 원인을 아직 확정하지 않았으며 앱·발행 주기를 변경하지 않는다.

## T — Task·Target

- 정식 **3 RPS·120초·3회**, 회차마다 1 RPS·30초 워밍업은 측정에서 제외한다.
- 회차당 정상 348건+probe 12건=360건. probe는 총 부하에 포함되며 10초마다 1건이다.
- 측정 요청·DB 저장·AI 완료를 대조하고 중복 0건, 서버 AI/WAF 경로 p95 각각 3초 이내를 확인한다.
- probe의 두 출처 저장·알림 수신·DOM·대표 위협 행과 종료 60초 내 업무 완료·연속 lag 0을 확인한다.
- 세 회차 모두 PASS해야 단계 PASS. 평균·p50·p95·p99·최대·표본·미확인을 기록하며 p99는 참고값이다.
- 1 RPS와 앱 SHA·이미지·실행기·계약 조건을 대조한다. 5 RPS 이상이나 개선 작업은 이번 범위에 포함하지 않는다.

## A — Action

- 시작 전 읽기 전용 조회에서 서비스 9개 실행·필수 lag 0, 1 RPS와 앱 SHA·이미지·실행기 소스 일치를 확인했다.
- 실제 관리자·기존 DB 인증을 사용하고 이번 세 회차 동안 숨김 입력을 메모리에서만 재사용한다.
- 발생기 IP 하나만 임시 제외하며 회차별 시험 등록 정리·원래 설정 복구를 확인한다. 실패·원복 미확인 시 다음 회차를 시작하지 않는다.

## T — Trouble·해석·다음 작업

- 최초 [r01](20261105T224809+0900-ec2-e2e-rps3-r01.md)은 DB 사전 인증의 root 1045로 중단됐다. 요청 0건·WAF 변경 없음이며 BLOCKED/INCONCLUSIVE 원본을 보존했다. 재인증 후 새 ID r02~r04의 세 회차를 수행했고, 사전 인증 실패를 성능 실패나 반복 표본으로 합산하지 않았다.
- 1 RPS 대비 입력을 3배로 높인 이번 혼합 부하에서도 서버 p95 3초와 정합성 목표를 충족했다. 현재 결과만으로 포화 지점·최대 EPS·장시간 안정성을 판단하지 않는다.
- 순간 consumer lag 최대는 업무 미완료 건수와 동일하지 않다. AI Consumer는 자동 커밋을 사용하므로 완료 trace·DB 집합·부하 중 완료 EPS·lag 추이를 함께 확인한다. 원인은 추가 근거 없이 커밋 주기나 AI 추론으로 확정하지 않는다.
- WAF는 회차당 12표본·합산 36표본이며 p99는 참고값이다. probe는 고정 0.1 RPS로 전체 3 RPS에 포함되며, WAF 탐지 이벤트만의 처리량 한계 실험은 아니다.
- DB 행수는 통계의 추정값이고 1 RPS 이후 데이터가 늘었다. DB 초기화 없이 로그·탐지·실험 증거를 보존했다. DB 상세 수치와 컨테이너 CPU에는 관측·관리자 화면·healthcheck 비용도 포함된다.
- 최신 CPU 크레딧 잔량은 미수집이며 과거 P0 값을 최신값으로 사용하지 않는다. PC HTTP·브라우저 관측과 EC2 서버 SLO도 구분한다.
- 숨김 입력은 이번 세 회차 안에서 메모리로만 재사용하고 종료 시 참조를 해제했다. 계정·비밀번호·토큰·발생기 IP는 공유 보고서·증거에 기록하지 않았다.
- **다음:** 같은 계약의 개선 전 5 RPS·120초·3회. 5 RPS는 아직 실행하지 않았다. 원인 조사·개선은 부하별 기준선과 증거를 비교한 뒤 진행한다.

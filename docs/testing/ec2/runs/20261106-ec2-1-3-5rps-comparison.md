# 2026/11/06 — EC2 개선 전 1·3·5 RPS 비교

[EC2 목차](../README.md) · [5 RPS 상세](20261106-ec2-5rps-baseline-review.md)

각 단계는 120초·정식 3회다. 5 RPS는 정밀 시계·입력 해상도 검증 버전이 달라 단순히 모든 조건이 동일하다고 표현하지 않는다. 앱·이미지·SLO는 별도 대조하고 DB 증가·외부 네트워크·관측 비용도 고려한다.

| 입력 RPS | 요청/로그/AI 완료 | AI 서버 p50 / p95 / p99 ms | WAF 서버 p95 ms | 판정 |
| --- | --- | --- | --- | --- |
| 1 | 360 / 360 / 360 | 621.789 / 1004.396 / 1149.121 | 608.147 | PASS |
| 3 | 1080 / 1080 / 1080 | 664.372 / 1016.607 / 1108.587 | 613.642 | PASS |
| 5 | 1800 / 1800 / 1800 | 728.638 / 1049.283 / 1178.251 | 541.001 | PASS |

- 세 단계 모두 서버 AI/WAF p95 3초와 정합성·알림·복구 기준을 충족했다.
- p95는 원본 표본 합산값이며 p99는 참고값이다. WAF·브라우저는 단계마다 36표본이다.
- 순간 consumer lag와 업무 미완료는 다르므로 완료 trace·DB·시간별 EPS를 함께 본다.
- probe는 고정 0.1 RPS이고 일반 요청을 늘린 혼합 부하다. 탐지 이벤트만의 최대 처리량으로 설명하지 않는다.
- 5 RPS까지의 결과로 최대 처리량·knee point를 확정하지 않는다. 코드 개선 전 관측이므로 개선 성과로 표현하지 않는다.

고정 조건 대조에서 3 RPS는 입력률 외 차이가 없었고, 5 RPS는 계측 소스 해시와 Chrome 156.0.8078.80 → 156.0.8078.81 차이를 확인했다. 앱 SHA·이미지·나머지 도구·SLO는 일치한다. 브라우저 지연의 차이를 서버 개선 효과로 설명하지 않는다. 상세 조건·원본 집계 해시는 같은 이름의 JSON을 참고한다.

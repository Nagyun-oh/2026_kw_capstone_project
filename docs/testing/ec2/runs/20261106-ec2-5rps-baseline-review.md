# 2026/11/06 — EC2 정식 5 RPS 기준선

[EC2 목차](../README.md) · [확정 기준](../P8.md) · [1 RPS](20261105-ec2-1rps-baseline-review.md) · [3 RPS](20261105-ec2-3rps-baseline-review.md)

## S — Situation

정식 1·3 RPS는 각각 120초·3회 모두 PASS했다. 개선 전에 5 RPS의 서버 지연·처리 완료·적체·자원을 측정해 세 단계 기준선을 확보한다. 앱·수집/발행 주기는 유지했다. 실행 중 발견한 시각 검증 문제는 계측에서 보완하고 변경 전후 회차를 분리했다.

## T — Task·Target

- 정식 **5 RPS·120초·3회**, 회차마다 1 RPS·30초 워밍업은 측정에서 제외한다.
- 회차당 정상 588건+probe 12건=600건. probe는 총 입력 안에 0.1 RPS로 포함된다.
- 서버 요청→AI/WAF 커밋 p95 각 3초 이내, 요청·DB 저장·AI 완료 대조와 중복 0건.
- probe 두 출처 저장·알림 수신·DOM·대표 행과 종료 60초 안의 업무 완료·연속 lag 0 확인.
- 3회 모두 PASS해야 단계 PASS. 평균·p50·p95·p99·최대·표본·미확인을 남기며 p99는 참고값이다.
- 10 RPS 이상·장애 주입·병목 개선은 이번 실행 범위에 포함하지 않는다.

## A — Action

- 최초 시도 전 읽기 전용 확인에서 서비스 9개 running·필수 lag 0, 3 RPS와 앱 SHA·이미지·실행기 소스 일치를 확인했다. 이후 계측 보완 버전은 별도 해시로 구분했고, 최종 r05~r07은 서로 같은 버전으로 실행했다.
- 최초 준비 시 PC 여유 메모리 약 2.01GiB로 Chrome 실행 여유가 적어 사용자 앱 정리 후 다시 확인했다. 최종 세 회차의 관측 최소 여유 메모리는 PC 약 6.66GiB·EC2 약 4.65GiB였다.
- 앱 정리·숨김 입력 후 DB 상세 통계 인증과 시작 자원 조건을 확인하고 실행했다.
- 실제 관리자·기존 DB 인증을 숨김 입력으로 확인하고 세 회차 동안 메모리에서만 재사용했다. 종료 후 해당 입력 제어기 프로세스가 0개임을 확인했다.
- 발생기 IP 하나를 임시 제외하고 회차별 시험 등록 정리·원래 설정 복구를 확인했다. 다음 회차는 앞 회차 PASS·원복 확인 후에만 실행했다.

## T — Trouble·비교 제한·다음 작업

- r01은 1.52ms의 시각 구간 위반으로 중단됐다. 중단 시 전송 중 요청을 포함해 서버 493건 저장·AI 완료와 원복을 확인했다. 원본 INCONCLUSIVE는 보존했다.
- 첫 보완 버전 r02/r03은 각각 PASS였지만 r04에서 표시용 UTC 해상도를 실제 점프로 판단한 구현 실수를 발견했다. 표시 시각 차이는 11.13ms, 정밀 UTC·단조 시각 차이는 0.003ms였다. r04 서버 466건 저장·AI 완료와 원복을 확인하고 INCONCLUSIVE로 보존했다.
- 같은 교환 표본의 정밀 UTC·단조 시계 쌍과 Nginx/k6의 실제 1ms 해상도를 사용하는 버전으로 r05~r07을 새로 측정했다. 전체 262개 회귀와 중단 원본 HTTP 875표본의 오프라인 재검증을 통과했다. [원본 재검증](../evidence/20261106-5rps-precise-clock-replay.json).
- 이전 1·3 RPS와 계측 소스 해시가 다르고 Chrome도 156.0.8078.80 → 156.0.8078.81이다. 브라우저 알림 지연을 비교할 때 이 버전 차이를 고려한다. 앱·서버 지연 계산·3초 SLO·입력·중복·복구 기준은 유지했지만 시각 검증과 잠재적 추가 SSH 비용 차이를 비교 제한으로 기록한다. 기존 분포·판정은 재작성하지 않는다.
- WAF/브라우저는 36표본이며 p99는 참고값이다. probe 0.1 RPS는 고정하므로 WAF 이벤트 전용 처리량 한계 실험은 아니다.
- DB는 초기화하지 않아 데이터가 증가했다. 통계·자원에는 관리자·수집기·healthcheck 비용도 포함된다. 최신 CPU 크레딧 잔량은 미수집이다.
- 이번 5 RPS 범위에서 목표를 충족했으며 최대 EPS·knee point·장시간 안정성을 확정하지 않는다. 10 RPS 이상·장애 주입·성능 개선은 미실행이다.
- 다음은 세 단계의 구간별 지연·완료 EPS·lag·자원을 분석해 원인 가설을 정하는 작업이다. 추가 부하 상한은 별도로 확인한다.

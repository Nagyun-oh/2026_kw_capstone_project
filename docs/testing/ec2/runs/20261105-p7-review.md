## S — Situation

P0~P6의 준비 도구를 실제 HTTPS·관리자 브라우저·파이프라인에 연결할 필요가 있었다. 본 부하는 아직 실행하지 않았고 기존 탐지·자동 등록 정책은 유지했다.

## T — Task·Target

정상 요청 3건·검증된 시험용 로그인 요청 1건으로 서버 requestId → DB → AI/WAF → alertId → 실제 알림 수신·DOM을 대조한다. 임시 제외는 발생기 IPv4 하나만 적용하고 실험 뒤 원래 제외 목록과 블랙리스트 상태로 복구한다. 성능 SLO와 탐지율은 판정 대상이 아니다.

## A — Action

1. r01·r02는 시계 사전 검사에서 중단됐다. 요청·WAF 설정 변경은 없었다. r01은 상세 시계 표본이 남지 않아 일반 ValueError까지만 확인한다. r02는 wall-clock 구간과 단조 시계 RTT의 불일치 표본을 보존했다.
2. Windows Python 3.12의 기본 UTC 조회가 빠른 교환 중 거칠게 갱신되는 문제를 정밀 Windows UTC API로 보완했다. 임계값·시계 모순 검사를 완화하지 않았다.
3. 새 회차 r03에서 HTTPS 실제 원격 IP와 SSH 출구 IP 일치를 확인했다. 사용자가 EC2 관리자 브라우저에 직접 로그인했다. 자격 증명은 저장하지 않았다.
4. 기존 목록에 발생기 IPv4 하나를 추가하고 WAF만 재생성했다. 정상·probe 요청과 실제 브라우저 알림을 관측했다.
5. probe가 만든 자동 블랙리스트 항목만 관리자 세션·CSRF API로 삭제했다. 원래 제외 목록 복원·WAF 재생성·정상 접근을 확인했다. 원본 로그·탐지·알림은 보존했다.
6. 종료 후 별도 읽기 전용 수집으로 DB·AI 완료·lag·서비스·제외 목록·블랙리스트를 다시 대조했다.

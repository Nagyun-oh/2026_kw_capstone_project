## T — Task

## T — Target

- 기존 키·호스트 키 검증을 사용하고 비대화형 SSH 연결은 5초로 제한한다.
- 배포 SHA·이미지·스키마·초기 lag·자원·시계 등 수집 자료를 확보해야 P0 완료로 판단한다.
- 앱 부하·탐지 probe·서비스 재시작·DDL·DML·IAM·보안 그룹 변경은 수행하지 않는다.
- 접속·관측 실패는 미확인으로 기록하고 성능 실패·데이터 누락으로 해석하지 않는다.
- 수집기는 비밀값 제외·읽기 전용 SQL·제한 시간·실패 보존을 모의 검증한다. 실제 서버 실행과 구분한다.

## A — Action

1. 현재 브랜치·작업 트리·EC2 README·실행 설정을 확인했다. 기존 사용자 변경인 별도 배포 절차서 삭제는 유지했다.
2. 기본 샌드박스에서 SSH 시도는 소켓 접근 거부로 종료됐다. 이 결과는 EC2 서버의 거부 응답으로 간주하지 않았다.
3. 네트워크 접근이 가능한 실행으로 재시도했으나 `Connection timed out`으로 종료됐다. 원격 `git`·Docker 조회 결과는 받지 못했다. 연결 시도별 정확한 시작 시각은 따로 수집하지 않았으며 이 문서의 기록 시각과 구분한다.
4. 현재 접속 주소·기존 SSH 창의 접근 가능 여부를 사용자에게 확인 요청했다. 권한·보안 그룹은 변경하지 않았다.
5. 읽기 전용 수집기·모의 테스트·수집 가이드와 사용자 제공 배포 증거 요약을 추가했다.

# EC2 P0 읽기 전용 현황 수집

[EC2 진행표](README.md) · [공통 기록 규칙](../README.md)

P0는 부하를 시작하기 전에 실제 배포 버전·DB 구조·자원·초기 lag·시계를 기록하는 단계다. 성능 합격 판정이나 장애 주입은 하지 않는다. [사용자 제공 배포 확인](evidence/20261105-deployment-smoke-user-provided.json)과 이번 수집기의 신규 결과는 구분한다.

## 수집 범위

| 대상 | 남기는 내용 | 제한 |
| --- | --- | --- |
| 코드·이미지 | EC2 HEAD·변경 파일, 컨테이너별 이미지 태그·ID·digest·기동·health·재시작 횟수·자원 한도·로그 드라이버 | 체크아웃 SHA와 실행 이미지가 같은 버전인지 별도 대조. 레지스트리 주소는 제거 |
| 설정 | `.env.aws`의 지정된 키 존재 여부, 실행 중인 backend의 outbox·trace·WAF Consumer 활성화 여부, 관련 파일 해시 | 비밀값·`.env.aws` 원문·전체 Docker 환경을 출력하지 않음. 키 존재만으로 값의 정확성을 보장하지 않음 |
| DB | 핵심 테이블·연결 컬럼·collation·UNIQUE·외래 키·추정 행 수·크기, DB 시각·시간대, outbox 상태별 건수 | 기존 컨테이너 환경의 앱 계정 → 실패 시 root 순서. 접속 실패는 미확인으로 보존. DDL·DML·비밀번호 변경 없음 |
| Kafka | group·topic·partition·오프셋·lag | 한 시점의 표본. 빈 출력·조회 실패·미확인을 lag 0으로 판단하지 않음 |
| 호스트·시계 | CPU·메모리·디스크 여유·load average, chrony 오차·동기화 정보 | 성능 추이나 발생기와의 교차 시계 오차 측정은 P5에서 추가 |
| Nginx | 호스트·WAF의 응답 계측 헤더·전달 헤더·신뢰 프록시 지시문 유무, 설정 출력 해시 | 전체 설정·실 IP·인증 헤더 값은 저장하지 않음. 지시문 존재만으로 특정 도메인의 실제 HTTP 응답까지 증명하지 않음 |
| AWS | IMDSv2의 인스턴스 유형·리전·아키텍처, 선택적으로 CPU 크레딧 모드·최근 관측값 | IAM·보안 그룹·크레딧 모드 변경 없음. 권한·CLI·메트릭 미제공이면 미확인 |

수집기: [collect_ec2_inventory.py](../../../scripts/testing/collect_ec2_inventory.py). Python 표준 라이브러리만 필요하며 Linux의 실제 EC2 저장소를 지정해야 실행된다. 컨테이너 조회는 `sudo -n docker`로 하며 권한이 없으면 대기하지 않고 실패로 기록한다.

DB 조회는 `START TRANSACTION READ ONLY`와 SELECT당 3초 제한, 프로세스별 12초 제한을 사용한다. 큰 로그 테이블의 전체 `COUNT(*)` 대신 `information_schema.TABLES.TABLE_ROWS` 추정치를 남긴다. outbox 상태별 건수는 제한 시간 안에서 조회한다. 모든 명령의 수집 시각·종료 코드·시간·실패 유형을 남긴다. **조회 자체의 비용은 있으므로 본 부하 측정과 분리한다.**

## 로컬에서 원격 수집

아래는 **로컬 Windows PowerShell**에서 실행한다. 실제 주소와 개인 키 경로를 변수에만 넣고 Git·보고서에는 저장하지 않는다. 기존 SSH 접속이 정상인지 먼저 확인한다. 새 호스트 키는 별도로 확인하고, 검사를 끄지 않는다.

```powershell
cd C:\Projects\2026_kw_capstone_project
$ec2Host = '<현재 EC2 공인 주소>'
$ec2Key = '<기존 PEM 파일 경로>'
$p0Id = (Get-Date).ToString('yyyyMMddTHHmmsszzz').Replace(':', '') + '-ec2-inventory-r02'
$p0Dir = Join-Path $PWD "build/test-runs/$p0Id"
if (Test-Path -LiteralPath $p0Dir) { throw '이미 존재하는 회차입니다. 새 ID를 사용하세요.' }
New-Item -ItemType Directory -Path $p0Dir | Out-Null
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$p0Json = Get-Content -Raw -Encoding UTF8 .\scripts\testing\collect_ec2_inventory.py |
    ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=5 -o ConnectionAttempts=1 `
        -i $ec2Key "ubuntu@$ec2Host" `
        'python3 - --repo /home/ubuntu/2026_kw_capstone_project --include-cloudwatch'
if ($LASTEXITCODE -ne 0) { throw '원격 수집 실패. 빈 JSON을 성공 결과로 저장하지 마세요.' }
$p0Text = $p0Json -join "`n"
$p0Data = $p0Text | ConvertFrom-Json
if ($p0Data.schema -ne 'dualguard-ec2-inventory-v1') { throw '결과 형식이 다릅니다.' }
[System.IO.File]::WriteAllText((Join-Path $p0Dir 'inventory.json'), $p0Text, [System.Text.UTF8Encoding]::new($false))
$p0Data | Select-Object schema, inventory_status, started_at, ended_at, missing_observations
```

스크립트는 표준 입력으로 전달되어 EC2 체크아웃·앱 파일을 바꾸지 않는다. `r02`는 회차 형식의 예시다. 실제 r01~r03 기록과 중복되지 않는 새 ID·회차를 사용한다. 수집기 전체 순회에는 명령 수에 따라 1분 이상 걸릴 수 있으며, 개별 명령은 제한 시간 안에 끝난다. healthcheck가 없는 컨테이너의 health는 null이며 수집에서 제외하거나 unhealthy로 판단하지 않는다.

AWS CLI가 없거나 권한이 부족하면 `--include-cloudwatch` 조회는 미확인으로 끝난다. 설치·권한 변경으로 확대하지 않고 콘솔에서 같은 시점의 크레딧 모드·잔량을 별도 확인한다. IMDS 토큰·계정 ID·인스턴스 ID·실 IP는 결과에 넣지 않는다. 공식 조회 방식: [AWS IMDS](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html), [크레딧 모드 조회](https://docs.aws.amazon.com/cli/latest/reference/ec2/describe-instance-credit-specifications.html), [CloudWatch 조회](https://docs.aws.amazon.com/cli/latest/reference/cloudwatch/get-metric-statistics.html).

콘솔 보완 시에는 인스턴스의 **세부 정보 → 크레딧 사양**에서 standard/unlimited를 확인하고, **모니터링 → CPUCreditBalance** 그래프의 가장 최근 점에 마우스를 올려 값·시각·시간대를 함께 기록한다. 축 눈금은 잔량으로 사용하지 않는다. 자동 수집의 권한 거부·null을 수정하지 않고 별도 수동 증거를 연결한다. [AWS 모드 조회 안내](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/burstable-performance-instances-how-to.html), [크레딧 지표 안내](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/burstable-performance-instances-monitoring-cpu-credits.html).

## 결과 검토·완료 기준

1. `inventory_status`는 수집 상태다. `COLLECTED`도 실험 PASS를 뜻하지 않는다. `COLLECTED_WITH_GAPS`이면 `commands`, `parse_errors`, `missing_observations`와 null 값을 확인한다.
2. 서버 HEAD와 backend·frontend·ai 이미지 태그를 대조하고 digest를 고정한다. WAF·수집 설정·모델 lock 해시도 기준선에 남긴다. 모델 lock 해시만으로 실제 모델 바이너리 무결성을 검증했다고 기록하지 않는다.
3. 테이블·UNIQUE·collation·outbox 상태를 확인한다. 정상 경로 처리 확인과 구조 전체 확인은 다르다. SQL 접속 실패를 `.env.aws` 재작성·컨테이너 재생성·DB 초기화로 해결하지 않는다.
4. 필수 group·topic별 lag, 호스트 여유 메모리·디스크·시계, 인스턴스 사양과 크레딧 자료를 확인한다. 빠진 항목을 보완하거나 다음 단계로 넘어갈 수 없는 이유를 명시한다.
5. 원본은 `build/test-runs/<ID>/inventory.json`, 작은 공유 증거는 `docs/testing/ec2/evidence/`, 요약 보고서는 `docs/testing/ec2/runs/<ID>.md`에 남긴다. 날짜는 한국 시간의 `YYYY/MM/DD` 규칙을 따른다.
6. EC2 README의 P0 상태·남은 항목을 갱신한다. 이후 P1에서 측정 시간·발생기 위치·IP 차단 정책을 결정한다. 실제 부하는 P3~P8 준비 후 별도 회차다.

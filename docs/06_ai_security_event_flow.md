# AI 기반 보안 이벤트 처리 흐름


## 전체 시스템 흐름

1. 사용자가 외부에서 HTTP 요청을 보낸다.
2. 요청은 WAF를 거치며, 악성 패턴 또는 비정상 접근 여부가 1차적으로 필터링된다.
3. 필터링된 요청은 Web Server로 전달된다.
4. Web Server에서 발생한 접근 로그 및 요청 정보는 Spring 백엔드 서버로 전달된다.
5. Spring 서버는 수집한 로그를 표준화된 형식으로 가공한 뒤 Kafka로 전송한다.
6. Kafka는 백엔드 서버와 AI 탐지 서버 사이에서 로그 데이터를 전달하는 메시지 브로커 역할을 한다.
7. AI 탐지 서버는 Kafka로부터 로그 데이터를 전달받아 특징 벡터를 생성하고, 이상 행위 또는 공격 여부를 분석한다.
8. 분석 결과로 위험도 점수, 위협 유형, 알림 정보가 생성된다.
9. 생성된 탐지 결과는 Spring 서버로 다시 전달되어 보안 이벤트로 분류된다.
10. 원본 로그와 탐지 결과는 DB에 저장된다.
11. 최종적으로 대시보드에서 로그 현황, 탐지 결과, 위험도, 알림 정보를 시각화한다.

## 이벤트 판단 기준 예시

| 조건 | 결과 |
|---|---|
| 반복적인 로그인 실패 | Brute Force 의심 |
| 비정상적인 요청 빈도 | DDoS 의심 |
| 위험 키워드 포함 | Suspicious Activity |
| AI 이상 점수 기준 초과 | Anomaly Detected |

## AI 모듈 역할
- 로그 메시지 패턴 분석
- 위험도 점수 계산
- 이상 탐지 결과 반환

## 백엔드와 AI 모듈 연동 방식
- Kafka 기반 비동기 메시지 연동
- Spring 서버가 로그 데이터를 Kafka에 발행
- AI 탐지 서버가 Kafka Topic을 구독하여 로그 분석
- 분석 결과를 Kafka를 통해 Spring 서버로 반환
- Spring 서버가 원본 로그 및 탐지 결과를 DB에 저장
- 이러한 방식은 백엔드 서버와 AI 서버를 직접적으로 강하게 결합하지 않고, Kafka를 중간 메시지 브로커로 사용하여 안정적인 데이터 전달과 확장성을 확보할 수 있다는 장점이 있다.
